## Production runtime defects found

### 1. SmartProBono Legal AI routes returned HTTP 500

The public Legal pages rendered, but the actual POST endpoints failed in production:

- `POST /api/legal/chat` → 500
- `POST /api/legal/draft` → 500

The implementation depended on a configured Groq or OpenAI provider. The unified deployment must remain usable even when neither provider is present or a provider is temporarily unavailable.

Fix:

- added deterministic, preparation-only fallbacks
- Ermi now returns a factual organization/checklist response when AI is unavailable
- Legal Draft now returns a `DRAFT — FOR REVIEW` composed only from user-supplied facts
- missing jurisdiction/details remain explicitly marked or require confirmation
- provider errors are safely logged without returning provider details to the client

Branch runtime verification with no AI secret configured:

- `POST /api/legal/chat` → 200
- `POST /api/legal/draft` → 200
- `POST /api/generate` → 200

### 2. CI did not run the full test/lint/security gate

Before this audit, the PR workflow ran production build + copy safety only. It did not require lint, the unit/regression suite, or dependency auditing.

Fix:

The permanent PR workflow now requires:

1. `npm ci`
2. `npm run lint`
3. `npm test`
4. `npm run test:copy-safety`
5. `npm run build`
6. `npm audit --omit=dev --audit-level=critical`

CI uses Node 24.

## Architecture / authorization observations

### Strong points

- organization access is backed by Supabase Auth and membership/role checks
- organization intake changes are role-gated
- professional handoff remains tied to inventor/project authorization and explicit sharing
- partner metrics reject unauthorized access
- record reads/writes are scoped by the inventor pilot session
- request-size limits and public error hygiene are present
- recovery tokens are hashed and newer recovery claims are single-use
- generated IP copy has explicit legal-safety checks
- evidence uploads enforce ownership, size limits, and an allowed MIME set

### Remaining hardening items

These are not blockers for the audit fixes, but should stay on the security backlog:

1. **CSP is report-only.** It reports violations but does not yet enforce them; it also currently permits `unsafe-inline` / `unsafe-eval` for scripts where needed by the present stack.
2. **Rate limiting is process-local.** The current in-memory limiter is not globally durable across Netlify serverless instances. Public AI endpoints should eventually use a shared limiter/store.
3. **Inventor identity is still an accountless pilot-session model.** This is appropriate for the current pilot architecture, but the long-term unified platform should move inventor/legal users to one Supabase Auth identity model.
4. **Uploaded evidence is not malware-scanned.** Size/MIME/ownership checks exist; content scanning should be considered before broader professional download workflows.
5. **Next.js middleware convention is deprecated.** The current middleware works, but a future maintenance pass should migrate it to the current proxy convention.
6. **Umbrella content cleanup remains.** About, Contact, and the Terms copy still contain IP-specific language. Terms are explicitly marked draft and should receive legal review before substantive umbrella-wide changes.

## Release conclusion

The audit fixes are suitable for PR review and deploy-preview testing.

The current production deployment should not be considered fully healthy for SmartProBono Legal until the audit branch is deployed and both production Legal POST endpoints are re-tested successfully.
